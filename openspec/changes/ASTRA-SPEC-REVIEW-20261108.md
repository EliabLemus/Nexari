**2. Riesgos de regresión cross-spec**

- **Overrides frente al swap:** el alias de Rollup no garantiza la existencia de `node_modules/@rollup/wasm-node`, origen requerido por la copia. El arranque elimina antes `node_modules/rollup`, que podría contener ya la distribución WASM correcta. Un manifiesto conforme al spec de guía puede fallar en el pipeline.
- **Instalaciones intermedias:** el propio [prompt:321](/Users/openjaime/Projects/bolt.diy-nexari-main/app/lib/common/prompts/optimized.ts:321) muestra `npm install --save-dev vite`; la reescritura elimina la petición de añadir Vite. Los ejemplos de generación y la semántica del shell son incompatibles.
- **Arranques solapados y previews anteriores:** el [runner:208](/Users/openjaime/Projects/bolt.diy-nexari-main/app/lib/runtime/action-runner.ts:208) libera la secuencia tras dos segundos, mientras el arranque sigue activo. Otro pipeline puede modificar las mismas dependencias; un preview anterior puede aparentar éxito del nuevo intento.
- **StackBlitz:** conservar intacta su ruta de ejecución no asegura ausencia de regresión cuando el prompt compartido cambia sus dependencias.
- **Readiness frente a aplicación funcional:** respuesta HTTP, salida `VITE ready`, carga del documento y ejecución correcta de los módulos son condiciones diferentes. Un error del pipeline puede coexistir con un evento de readiness o una página de error.

**3. Criterios de aceptación faltantes o débiles**

- **Procedencia de la evidencia:** checkout/commit y estado del árbol, identidad del dev server que sirve la página, versiones/hashes de SDK y workers, estado del Service Worker y del filesystem guest. Una ejecución con código antiguo, worktree incorrecto o worker truncado debe clasificarse como **no evaluable**, sin atribuirla al spec.
- **Pipeline desde estado limpio y repetido:** proyecto generado y starter externo, con/sin overrides, dependencias añadidas, comandos compuestos, flags de arranque y variantes de gestores. La aceptación debe comprobar la secuencia completa y el código de salida exacto; el [test de fallo:175](/Users/openjaime/Projects/bolt.diy-nexari-main/app/lib/runtime/nexari-action-shell.spec.ts:175) actualmente comprueba el mensaje, pero no `result.exitCode`.
- **Cancelación y recuperación reales:** abort desde la UI durante cada etapa, ausencia de pasos posteriores, estado del filesystem recuperado y ausencia de procesos/eventos del intento anterior.
- **Generación real:** prompt y modelo efectivos, artefacto íntegro tras streaming, manifiesto recibido por el guest, caso estático y compatibilidad en ambos backends. Encontrar una cadena en el prompt no sustituye ninguno.
- **Preview completo:** bind sin respuesta, petición colgada, significado de 404/500, cierre/reapertura, desuscripción, render de contenido identificable y edición visible. El control de ausencia de StackBlitz debe cubrir iframe y workers: `performance.getEntriesByType('resource')` del documento principal no acredita por sí solo todo el tráfico.
